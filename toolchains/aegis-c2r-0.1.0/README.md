# Aegis-C2R 0.1.0

A working deterministic C-to-safe-Rust translation prototype for the deliberately bounded `S0-DEFINED-I32` C profile. The implementation is strict C11 and uses the clean Aegis 2.4.0 three-language toolchain (DXL + DXS + DXASM) with its C stage-zero bootstrap as an independent certificate path.

This release is intentionally narrow. It is an engineering proof-of-capability, not a claim that arbitrary C repositories can already be migrated automatically.

## What is implemented

- deterministic lexer, parser and canonical AST;
- fail-closed S0 semantic checker;
- safe-Rust emission with `#![forbid(unsafe_code)]`;
- checked signed-i32 arithmetic lowering;
- source/AST/Rust SHA-256 binding in JSON evidence;
- DXL, DXS and DXASM structural certificates;
- positive, negative, boundary, mutation and generated-vector tests;
- strict GCC and Clang builds, GCC `-fanalyzer`, ASan and UBSan gates;
- vendored clean Aegis 2.4.0 C-bootstrap source and its 11/11 release gate;
- optional `rustc` compile/run gate when Rust is installed.

## Build and verify

```sh
make clean
make check
```

The release gate contains 37 fixed checks. On the validation host used for 0.1.0 all 37 passed. `rustc` was not installed, so the additional Rust compiler/runtime gate is reported as `SKIP` rather than falsely counted as a pass.

## Use

```sh
make
build/bin/aegis-c2r check tests/positive/basic.c
build/bin/aegis-c2r translate tests/positive/basic.c \
  -o build/basic.rs \
  --ast build/basic.ast \
  --proof build/basic.json \
  --aegis-prefix build/basic
```

## S0 profile, in one paragraph

S0 admits signed 32-bit integer functions, initialized prefix locals, function calls declared before use, assignment, return, `if/else`, `while`, blocks, `printf("%d\\n", expr)`, `assert(expr)`, integer arithmetic, comparisons and logical operators. It rejects pointers, arrays, structs, floating point, globals, macros beyond the two accepted include lines, recursion, `for`, late/nested declarations, unsupported library calls and other out-of-profile syntax. See `docs/PROFILE.md` and the 26-page engineering manual.

## Release evidence

`evidence/FINAL_VALIDATION_REPORT.md` is the human-readable release record. `evidence/release_gate.log` and `evidence/release_gate.tsv` are generated by the actual gate.

## Claim boundary

The evidence proves behavior for the declared profile and tested corpus. It does not establish complete C semantics, repository-scale migration, formal verification, independent security certification, or superiority to established C-to-Rust systems.
